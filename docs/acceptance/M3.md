## 本地集成验证

`tests/e2e/test_m3_synthetic_journeys.py` 同时覆盖 v14 单动作和 v15 双动作旅程：真实 HTTP 入口和 Worker、实际本地 MCP 协议及合成上游、同 Scope 证据读取、人工审批、本地模拟器回执、Incident 关联和撤权后的证据拒绝。Jira 的响应丢失与对账在该旅程中验证；v15 批量旅程另行覆盖不同审批人、崩溃接管、规则撤销和独立未知状态。Redis 不可用由独立故障测试覆盖，不表示在同一旅程中注入该故障。

2026-11-14 定向运行 `tests/e2e/test_m3_synthetic_journeys.py`、`tests/e2e/test_synthetic_batch_journey.py`、`tests/integration/test_local_delivery_simulator.py` 与 `tests/fault/test_redis_outage.py`：**36 passed**。本地 MCP 旅程依赖项目内 `apps/mcp-server` 源码；迁移后组件缺失会导致测试失败。

## M4 可依赖的接口

M4 可在本地开发中使用已实现的 Run、Evidence、Incident、Action／Approval、SSE 和调度 API；动作发送需经过当前授权和明确审批，未知结果不能自动重发。接口的真实业务连接、生产可用性、数据保留和容量仍需按 M4/P0 计划独立验收。

以下事项在完成前不可标记为 M3 真实验收通过：真实 SeaTalk 回调和授权环境、真实 Jira/DoD/通知回执、冲突输入与交付的同一条旅程、完成态证据充分性及备份恢复后的动作对账。用户确认没有真实知识源，因此本地知识验证采用自建数据，不记录为企业知识验收。
