---
title: "动作策略：部署授权与撤销"
---

动作写入默认关闭：服务启动不会自动安装外部发送器，也不会从进程配置恢复数据库中的动作策略。管理员在受信主机维护部署配置，显式将 `service.action_grants`、`service.tool_permissions` 和 `service.connector_identities` 作为一个整体同步到同一数据库：

```bash
dod action-policy status --config /path/to/deployment.yaml
dod action-policy sync --config /path/to/deployment.yaml --expected-revision 0
```

授权项必须明确指定团队、Agent、冻结的工具版本引用、具名人类审批者以及完整的精确参数。首次同步使用期望版本 0；后续同步须先读取当前版本并传入 `--expected-revision`。旧版本的同步会被拒绝，避免过期配置覆盖撤权。同步不会发送任何外部动作。策略为空或尚未同步时不允许新动作；修改或撤销策略后必须再次运行同步命令，不能仅修改配置文件就认为已撤权。

同步使用短数据库写事务发布单调递增的版本。审批绑定该版本；策略变化后，旧审批不会因稍后恢复相同配置而重新生效。API、Worker、Dispatcher 和对账在各自数据库事务中读取当前版本。已提交的发送标记是授权的线性化边界：在该边界之后请求可能已经发出或正在发出；撤权不能撤回该次派发，应按实际回执或未知结果对账。

策略配置和同步权限必须由部署管理员控制，不能由普通 Agent 用户控制。配置不应包含密码、令牌或其他凭据；认证信息应只使用部署方的密钥引用。数据库恢复仍按 SQLite 恢复手册隔离，必须先核对历史 Action 和 Outbox，不可在恢复副本上盲目重发。

当前实现只提供本地合成连接器测试。真实 Jira、SeaTalk、DoD 发送器及其目标白名单尚未装配；不要将该命令的成功解释为外部投递已验证。

## 人工重试

只有可信适配器明确证明请求未发送，且自动重试八次后仍失败时，具名审批者才能使用独立幂等键请求人工重试。原 Action 和 Outbox ID 保持不变，`attempt` 保留累计次数；每次人工请求仅允许一次额外尝试。审批未过期、当前策略版本、原发起人与审批者权限及 Scope 均须仍有效。已发送但结果未知的动作不得人工重发，应先由可信连接器查询事实并对账。

自动退避可能跨越 30 分钟审批有效期；过期后不会继续派发。对于只经历了可靠确认未发送的失败、且当前范围、参数、工具版本、部署策略及发起人和审批人权限均未变化的 Action，具名审批人可使用幂等键请求重新审批。系统创建新的 30 分钟审批记录，不延长或覆盖旧记录；重新批准后沿用原 Action、Outbox 和累计尝试次数，仍遵守最多八次自动尝试。结果为 unknown 的动作不能使用此流程重发，必须先查证对账。
