# 工作流目录与详情页设计

## 目标

让管理员先看懂八种 Agent 工作流的用途和限制，再进入详情查看执行结构。界面统一使用“工作流”；节点连线区域称“执行结构”。保留现有语义 `graph_id`、八图目录和 `/app/graphs` 地址。

## 目录

导航项和页面标题改为“工作流”。页面首先展示可点击的工作流卡片，按推荐与实验分组。卡片显示名称、简介、运行入口、已绑定 Agent 数，以及实验限制；整张卡片都有明确的“查看详情”入口。能力对比表移到卡片之后，作为可展开的辅助信息。八张图全部可见，合成告警三图的本地测试限制和知识问答的来源验收提醒始终可见。

## 详情

采用用户选定的 B 方案。标题区展示工作流名称、状态、简介、运行入口与已绑定 Agent 数。主区域左侧是执行结构画布，右侧是节点说明面板；点击或键盘选择节点，面板更新节点作用、读取、产出和消耗。默认选中第一个实际执行节点。条件边和回环有清晰标签，节点类型使用颜色与文字双重提示。窄屏时画布和说明上下排列，复杂图可在画布内滚动。适用、不适用、运行前提、执行步骤和高级 ID 放在画布下方的独立信息区；关键限制保留在标题附近。

## 路由与错误

直接打开或刷新 `/app/graphs/<graph_id>` 应返回前端入口并正常加载详情。服务端仍拒绝资源目录下不存在的文件，以及非 HTML 请求；只为 `/app/graphs/` 后的语义 ID 放行包含点号的前端路由。目录和详情的无凭据、加载中、加载失败与空数据状态保留明确提示。

## 实现边界

改动集中在 Vue 目录视图、执行图组件、局部样式与 FastAPI 前端路由。API 数据形状、图执行逻辑、图绑定权限保持现状。不引入新的图形库。更新产品文档中的用户可见名称。

## 验证

前端测试覆盖目录入口、状态与限制、节点选择和详情信息。后端测试覆盖带点号详情的 HTML 刷新与缺失静态资源的 404。运行前端测试、类型检查、构建和相关后端测试；在浏览器检查目录、简单图和带分支的 SOP 图，并刷新详情页。
