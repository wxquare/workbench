title: "共享技能库：Skill 管理、发布与 Agent 绑定"
---

## 设计状态

用户已确认产品范围：Skills 展示当前团队的技能库，Agent 从库中选择需要的技能，而不是为每个 Agent 建立一套独立技能。实施状态以代码及测试结果为准。

## 目标与边界

- 在 Skills 页面完成新建、编辑草稿、内容查看、发布与版本历史查看。
- 允许一个已发布 Skill 被同一团队的多个 Agent 绑定，绑定明确版本。
- 在 Agent 页面完成选择、解绑、升级和回退，再沿用保存草稿与发布流程。
- 让 `dod.v18` 实际消费已绑定的文本技能，而不是只保存引用。
- 沿用工作台现有认证、权限、并发控制、幂等、版本快照及对象完整性校验。
- 本期不做跨团队市场、远程 Git 拉取、脚本执行、自动工具授权、自动技能选择或模型驱动的资源加载。
- 首个完整编辑流程管理 `SKILL.md`。原有受控种子、Git 与 Artifact 导入能力保留，不在编辑单文件时静默丢弃导入包的其他资源。

## 已有基础

前端 `Skills` 路由仍使用占位组件。后端已有 Agent 级导入与发布 API、受控文本包校验、不可变对象快照，以及 `SkillLoader`。

`ProfileDraft.skills` 与 `RunContext.skills` 已采用 `VersionRef`。Agent 发布和任务受理已经能够固定版本引用；资源归属校验允许团队级 Skill，也允许当前 Agent 自己的私有 Skill。`dod.v18` 目前没有将 Skill 文本加入模型请求。

相关模块包括 `api/skills.py`、`skill_management/`、`application/profiles.py`、`runtime/graphs/conversation_qa.py`、`cli/worker.py`、`views/Agents.vue` 和 `router.ts`。

## 产品交互

### Skills 页面

采用现有管理页面布局：可搜索的技能列表、技能详情和编辑区，不增加营销页面。列表包含名称、描述、发布版本、草稿状态和更新时间。

新建时输入稳定的英文标识、描述和 Markdown 指令正文。由结构化字段生成合法的 `SKILL.md` 元数据，不通过字符串拼接处理 YAML。发布后标识不可修改；描述与正文通过新草稿更新。

详情区支持草稿编辑、保存、发布，以及只读查看历史版本。未保存修改、加载失败、无权限、无发布版本、存储不可用和并发冲突均有明确状态。切换技能、离开页面或发布前处理未保存内容。只读用户不能触发写操作。

Markdown 展示不得执行 HTML、脚本或不安全链接；沿用仓库现有安全渲染模式。操作使用现有组件库图标、确认框与通知。

### Agent 配置

增加技能选择区，列出当前团队可绑定的已发布技能，显示名称、描述、选中版本和最新发布版本。可多选，每个 Skill 只能绑定一个版本，默认新增绑定选择最新已发布版本。

已有绑定不得因分页、搜索、版本缺失或列表请求失败而被清空。失效引用显示错误并阻止误发布，不用最新版本静默替换。技能详情可跳转到 Skills 页面。

选择只修改 Agent 草稿。保存并发布 Agent 后，新任务才使用新绑定；Skill 发布本身不修改任何 Agent。多技能按显式保存的顺序组装，保持确定性，不引入本期不需要的拖拽排序。

## 数据与版本

团队库中的新 Skill 使用现有团队归属和 `agent_id = NULL` 表达，不引入新的 Workspace 或伪造管理 Agent。

为团队技能新增可持久化草稿，字段至少包含 `team_id`、`skill_id`、描述、`SKILL.md` 内容、revision 及时间。草稿与已发布版本分离；发布版本不得原地编辑。使用现有 Skill 的单调 revision 作为并发控制，发布版本号独立单调递增，不假设每次草稿保存都产生发布版本。

数据库确保同团队内团队技能标识唯一，不能依赖可空列的普通唯一索引去重。新增约束与草稿表通过追加维护迁移交付，不修改历史迁移快照，不删除或替换用户当前数据库。同步更新当前 schema、迁移 head 和就绪检查契约。

旧私有 Skill 保持其原归属、对象和引用，已有 Agent 与 Run 可继续读取。不得自动扩大可见范围或重新计算既有内容哈希。首次团队库只允许选择团队级技能，Agent 已有私有绑定仍显示并保留。私有技能迁入共享库需要显式管理操作，不属于本次自动部署步骤。

## API 与权限

新增独立团队库 API，不依赖选中 Agent：

| 方法与路径 | 用途 |
| --- | --- |
| `GET /v1/skills` | 分页、搜索团队技能列表 |
| `POST /v1/skills` | 创建技能与初始草稿 |
| `GET /v1/skills/{skill_id}` | 读取技能、草稿与发布摘要 |
| `PATCH /v1/skills/{skill_id}` | 更新草稿 |
| `POST /v1/skills/{skill_id}/publish` | 校验并发布草稿 |
| `GET /v1/skills/{skill_id}/versions` | 分页查看不可变版本 |
| `GET /v1/skills/{skill_id}/versions/{version}` | 读取某个已发布版本及其指令内容 |

写入使用 `Idempotency-Key`；修改与发布要求 `If-Match`。发生 revision 冲突返回 `409`，前端保留本地内容，要求刷新或重新编辑，不自动覆盖他人修改。同一幂等键重放返回原结果，不新增版本。

授权以当前数据库成员身份为准。团队级普通用户可读库；维护者可创建与保存草稿，管理员可发布。Agent 限域身份和 connector 身份不能借用团队库 API 取得团队级管理权限或读取未授权草稿；Agent 运行时仅可读取其任务已固定的已发布版本。跨团队资源按既有模式返回不可见。

保留原有 Agent 级导入发布接口以支持既有流程，其结果保持原归属。团队库不通过其中某个 Agent 代办发布。新的单文档发布为同步、有限大小操作，不为了存储一份文本新增异步管理任务。

## 发布与存储

复用 `validate_bundle`、manifest 和 `LocalSkillObjects`：构造受限文本包，验证名称、元数据、路径、大小及内容，再写入内容寻址不可变对象。对象成功落盘后，事务内重验权限和 revision，创建版本记录并更新 Skill 的发布状态。

对象写入成功而数据库事务失败时，允许留下未引用的不可变对象，不得形成数据库指向不完整对象的版本。垃圾回收不属于本期。没有 `skill_object_root` 时发布明确失败，不显示成功。

API 与 Worker 使用同一受控持久对象目录。在本地部署配置中显式配置该目录，并更新启动手册；不把 `.agents/work/` 或临时目录作为运行依赖，不修改密钥值。

## 运行时生效

在 Worker 组合根配置 SkillLoader。`dod.v18` 对当前 Run 冻结的每个绑定依次读取 `SKILL.md`，复用加载器对租约、成员、归属、发布状态、版本与内容摘要的检查，不查询最新 Skill 内容代替固定版本。

只将验证后的文本指令加入模型上下文，并标明技能名称和版本。基础安全约束与 Agent 系统指令优先于 Skill；正文不能修改运行权限。附带资源本期不自动展开，不能声称脚本、工具或外部查询已执行。

最多绑定 16 个不同 Skill，注入文本总量上限 64 KiB，单个绑定不得重复同一技能的不同版本。Agent 保存、发布及任务受理执行一致的约束。模型预算估算与历史筛选必须包含最终 Skill 指令，空间不足时按现有历史窗口策略减少历史；当前问题、系统指令与技能本身超限时，在发起模型调用前明确失败，不静默截断技能。

未绑定 Skill 的 v18 保持现有行为；其他图的运行逻辑本期不变。缺失对象、摘要错误、撤权、绑定内容不可读或存储未配置时，返回明确的技能不可用结果，不在缺少技能的情况下伪装为完整成功。该结果不暴露其他团队资源信息。

## 验证与验收

后端覆盖技能草稿与版本生命周期、名称冲突、非法元数据、角色和团队隔离、Agent 限域身份、幂等重放、并发冲突及不可变对象校验。迁移验证新数据库和现有 Agent 数据库升级，确认 Agent、任务和私有技能不丢失。

Agent 测试覆盖一个共享 Skill 绑定多个 Agent、解绑、显式升级及回退、重复绑定拒绝、不可见引用拒绝和草稿/发布隔离。

执行测试检查实际模型请求包含正确技能文本与版本，不只判断答案看起来是否变化。覆盖 v1 任务固定后发布 v2、已有任务仍读取 v1、新 Agent 发布后读取 v2；覆盖缺失对象、篡改、撤权、超限及历史预算计算。使用模拟模型，不调用付费模型冒充验收。

前端覆盖列表、空态、编辑与发布、版本查看、选择器、未保存提示、冲突处理，以及切换令牌或 Agent 时丢弃过期异步响应。

浏览器端到端使用隔离测试数据完成：创建共享技能、发布 v1、两个 Agent 分别绑定发布、提交 v18 任务、检查模型请求、发布 v2、验证未升级 Agent 不受影响，并检查桌面与移动端布局。

发布前运行相关后端测试、完整前端测试、类型检查、生产构建和浏览器验收。运行开发服务时提供实际地址，不占用用户的 8000 端口；临时测试完成后停止自身测试进程。

## 部署要求

发布时先备份数据库和 Skill 对象目录，停止会读写数据库的服务，执行追加迁移，再部署构建产物，确认 API 与 Worker 共享对象目录后重启服务。仅发布 Skill 内容或 Agent 绑定不要求重启；首次升级代码、迁移或改变部署级对象目录需要重启。

本次设计与实现不自动创建业务技能，不改写 DoD Agent、投资助手的提示词或现有绑定，也不擅自提交真实模型调用。
