# 多文件 Skill 草稿设计

## 目标与范围

将共享 Skills 页从单个 Markdown 正文编辑扩展为完整资源包的草稿编辑、发布和历史版本查看，并完成迁移、兼容性、前后端及运行时验证。

- 一个 skill_id 继续最多拥有一份草稿，一份草稿包含多个文件。
- 草稿内容保存于数据库 JSON；发布文件继续使用现有 LocalSkillObjects + manifest，不在本次扩展 S3 装配。
- 支持 UTF-8 文本、脚本源码和 PNG/JPEG/GIF/WebP 图片。脚本是可编辑和发布的资源，不隐式执行；.claude 资源和自动执行声明继续禁止。
- 不增加多人实时协作、多草稿分支、脚本运行、S3 接入或模型自动展开参考文件的行为。用户已确认需要图片和脚本资源。
- 不修改 Agent 版本绑定、Run 冻结引用和已发布对象的不可变规则。

## 方案比较

1. DB JSON 文件映射（采用）：一条草稿记录保存完整包，适合当前小型文本 Skill；整包 CAS 防止覆盖，前后端改动集中。
2. 文件明细表：适合文件级修订和协作，但需要额外文件事务与快照机制，当前没有该需求。
3. 草稿对象化：减少数据库内容体积，但增加暂存对象、编辑引用和清理机制，不采用。

## 数据模型与迁移

- 增加 Agent migration 0006_multifile_skill_drafts，并新增不可变 schema_agent_v6 快照。
- skill_drafts.content 替换为 files_json TEXT NOT NULL，其余字段及主键、唯一约束、团队外键不变。
- files_json 保存 canonical JSON 对象：相对文件路径 -> {encoding: "utf-8" | "base64", content: string}；文本/脚本使用 UTF-8，图片使用严格 Base64。API 也接受字符串值作为 UTF-8 简写。
- 迁移将每条旧 content 无损包装为 {"SKILL.md": {"encoding": "utf-8", "content": old_content}}，保留所有身份、描述、时间、修订号和发布记录。
- 实现采用现有 SQLite 原生列重命名和参数化数据回填，历史 schema/migration 文件保持不变。
- readiness/doctor 应认识新旧 revision，只允许当前 head 用于运行，旧库提示显式维护迁移。
- 当前维护入口将“非最新版本且存在运行数据”统一按旧 Graph ID 迁移拒绝，需调整为仅 0001–0004 的升级保留该限制；0005 -> 0006 必须支持已有 Agent/Profile/Run 数据，无需清库。
- SKILL.md 的草稿值继续是正文；name/description 来自表字段，发布时自动生成 YAML front matter。附件内容按字节原样发布。
- 草稿 JSON 是唯一权威源，不保留第二份数据库 content 镜像。

示例：

```json
{
  "SKILL.md": {"encoding": "utf-8", "content": "分析日志时区分事实与推测。"},
  "references/errors.md": {"encoding": "utf-8", "content": "# 错误码\nPAY-1001：下游超时。"},
  "templates/report.md": {"encoding": "utf-8", "content": "# 报告\n## 证据\n## 下一步"}
}
```

## API 与旧客户端兼容

- 创建和保存接口新增 files: Record<string, {encoding: "utf-8" | "base64", content: string} | string>；新编辑器提交整个文件映射，文件删除即从映射移除。
- 保留旧请求 content 参数：创建时映射到单个 SKILL.md；保存时仅替换已有草稿的 SKILL.md，保留其他文件。
- files 与 content 同时提供时必须一致，否则 422，避免两份冲突正文。
- 草稿响应返回 description、files 和派生的 content 兼容别名；content 始终由 files["SKILL.md"] 计算。
- 历史版本响应保留原 content（完整生成的 SKILL.md），增加 files，返回该版本所有资源，文本以 UTF-8 返回，图片以 Base64 返回。
- version 列表继续返回现有 VersionRef 形状，Agent 页面无需修改绑定协议。
- 旧 manifest 对象和旧 ZIP bundle 读取继续可用。
- 列表响应不返回完整草稿或完整版本文件，避免列表放大。

## 校验与并发

- 必须包含大小写准确的 SKILL.md，正文必须非空。
- 描述沿用最多 1000 字符；SKILL.md 正文沿用最多 32000 UTF-8 字节。
- 草稿至多 64 个文件，单个附加文本/脚本最多 256 KiB，单张图片最多 2 MiB，解码后的文件总大小最多 8 MiB；这些是编辑草稿边界，不改变已有导入包的全局限制。
- 文件路径最多 256 字符；禁止绝对路径、空路径、反斜线、NUL、空目录段、.、..，并拒绝文件与目录前缀冲突，例如 a 与 a/b.md 并存。
- 复用现有 bundle 校验并为共享草稿发布显式启用脚本与二进制资源。旧专属导入默认限制不变；禁止文本 NUL，图片校验扩展名与文件签名一致。
- 允许新建空的附加文本文件，但 SKILL.md 必须有正文。
- 单份草稿仍使用 skills.revision + If-Match 进行整包 CAS，文件操作和描述一起保存；重命名不产生第二份草稿。
- 创建/保存的幂等请求编码上限增为 12 MiB，仅对这些路由生效，容纳 JSON 转义和兼容字段；其他操作保持原限制。
- 同一幂等键/相同完整文件映射重试返回原响应；同键不同附件内容冲突。

## 发布与历史读取

1. 检查权限、幂等记录、Skill 状态和草稿 revision，读取完整 files_json。
2. 校验映射，为 SKILL.md 生成现有 front matter，其他文件保持内容不变。
3. 构造并验证完整资源包，生成每个文件的哈希和资源集合哈希。
4. 复用 write_manifest，将所有文件与 manifest 写入对象目录；相同内容自然复用。
5. 在写事务中重新校验权限、revision、幂等性，新增 skill_versions，推进 skills.revision 并同步描述，写入回执和审计。
6. 保留草稿；旧版本和旧 Run 继续使用旧 manifest。任一文件缺失或摘要不匹配时版本读取失败。

文件写入仍在 DB 写事务之前，失败可能留下未引用对象；本次不引入垃圾回收器，也不删除旧对象。

## 编辑界面

- 描述和技能标识保留；增加文件列表、当前文件内容编辑区和文件数显示；提供图片上传、预览和替换，脚本使用文本编辑器。图片只使用受限 image MIME 的 data URL 展示。
- 默认选中 SKILL.md，其编辑标签保留“技能指令”，并说明 YAML 元信息发布时自动生成。
- 通过路径输入新增文件；当前文件可重命名、删除；SKILL.md 不允许删除或重命名。
- 修改任何文件、路径、描述均进入 dirty 状态；切换文件不会丢失编辑，切换 Skill/离开页面保留现有未保存提示。
- 加载/保存/发布期间禁用对应文件操作，保持现有请求 generation 防止旧响应污染新 Skill。
- 历史版本以只读文件列表和内容区展示，包括 SKILL.md 及附件；查看历史不覆盖草稿。
- 界面不向用户暴露哈希对象存储等实现细节。

## 用户范围确认

2026-11-23 用户要求“要支持图片和脚本。暂时不需要接入s3”。本修订据此扩展草稿资源类型，保留脚本执行边界。

## 验证与验收

- 迁移：旧草稿正文含中文/换行/JSON 样式文本时无损迁移；迁移可在存在 Skill、版本和 Agent 配置的数据上执行；新建库/迁移库通过 readiness 与外键检查。
- API：多文件创建、重开、编辑、重命名、删除、发布、历史完整读取；空附件支持；缺少主文件、越界路径、前缀冲突、非法图片、非法 Base64、体积超限被拒绝且不写草稿。
- 兼容：旧 content 创建和保存继续有效，旧保存不会删除附件，两个字段不一致拒绝，旧单文件发布内容哈希保持一致。
- 一致性：旧 revision 不能覆盖任何文件；同键重试不会重复发布；对象存储错误不会产生有效版本。
- 版本：v1 与 v2 附件内容隔离，未变化文件复用；SkillLoader 在有效冻结执行中按路径读取已发布附件。
- 前端：图片上传/预览/替换、脚本编辑、新建、切换、重命名、删除文件，保存后重开，查看历史附件，锁定主文件，未保存提示和加载状态。
- 回归：共享 Skill、导入与 bundle 验证、Skill 运行时加载、Agent 绑定、存储 schema/migration 测试；Web Vitest、typecheck 和 production build；更新架构/运维/接口文档并执行 docs 检查。
